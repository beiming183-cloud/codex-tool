# Codex 工具箱

一个可配置的 Windows 桌面工具箱：检查多条代理线路的公网出口，读取正在运行的 Clash 内核和应用连接，查看账号额度，并在指定校园网下自动限制指定代理程序联网。

原生 WPF 界面，中文显示，侧栏与分组设置参考 macOS 系统设置的布局习惯，保留 Windows 原生窗口与键盘操作。与 OpenAI、Apple 或 Clash 官方无隶属关系。

## 使用

Windows 10/11 x64。便携版包含 .NET 运行时，解压后直接打开 EXE；无需安装 Python、Node 或 PowerShell 模块。机器需保留系统自带 Windows PowerShell。

1. 先打开 Codex 并登录，再打开工具箱。首页会自动检查，不用添加线路或填写固定 IP。一个窗口、多个窗口和 CLI 分别判断。
2. 查看额度：进入“额度浮层”，工具自动寻找运行窗口、安装位置与对应登录目录，点击“添加浮层”。已存在的旧浮层会被识别，避免重复添加；没有窗口连接接口时使用独立浮窗。无需安装 Node。
3. 校园网保护：查看当前网络识别结果，需要时确认一次。点击启用并通过 Windows 管理员授权，才会安装自动保护。规则与受限程序放在折叠选项里。
4. 日常保持默认即可。手动代理检查在首页“自定义线路”；Clash 状态、应用连接、公网 IP 在“设置 → 诊断工具”。高级接口与配置迁移默认折叠。

额度查询只读取已有 access_token，不刷新 refresh_token，不改变登录状态；不会发送登录文件到第三方。登录账号改变后会暂停查询并要求重新查找。额度接口属于客户端接口，未来可能变化；过期或失败会显示重试提示。

登录位置优先匹配窗口自己的目录。默认账号使用当前 Windows 用户的 .codex；兼容 Cockpit 把界面目录与登录目录分开的映射，不依赖此电脑的账号或端口。无法明确对应时不会借用另一个账号的登录文件，可在“找不到账号？”中选择连接方式与登录目录。工具箱打开期间每分钟更新；直接添加要求 Codex 已提供本机窗口连接接口，不会自动重启客户端或更改启动参数。

自动内核识别优先唯一的 Clash Verge / 择优版桌面内核，避免被 Cockpit 等启动器的 Mihomo 辅助进程干扰。仍有多个候选时，在高级连接设置指定接口。

**观测边界：** 代理出口实测只证明该代理的公网出口。应用连接展示 Clash 已采到的 TCP 请求和代理链；未采到请求时保持“尚未确认”，不推断模型请求、UDP 或所有账号环节已经通过。

### 窗口与界面缩放

- 可自由调整窗口、最大化和还原；界面右下角提供缩小、当前比例、放大，范围 75%–150%。点击百分比恢复 100%。缩放与侧栏偏好保存在此电脑的配置中。
- Ctrl + 加号 / 减号、Ctrl + 鼠标滚轮调整；Ctrl + 0 恢复。已打开的工具弹窗会同步缩放。
- 窗口变窄或字号放大后，侧栏自动收起，点击顶部菜单可切换页面；线路与额度卡片按可用宽度和实际数量切换一至三列。较矮窗口精简页头，内容支持鼠标、触摸纵向滚动。
- 主窗口默认 1120×800 DIP，最小 600×460 DIP；弹窗会限制在当前显示器可用区域内。程序保留 Windows 原生边框与每显示器 DPI 感知，不会修改 Windows 的显示缩放设置。
### 怎样看多 IP 与一致性

- 按**同一实例**判断，不把不同账号或不同窗口各自的 IP 差异当成故障。
- 同轮不同代理上下文采到同地址族的不同公网 IP：提示多个出口 IP；同一路采样在短时间换 IP：提示短时切换；和过去相比改变：提示历史变化，动态 IP 变化不直接判为故障。
- IPv4 与 IPv6 双栈各一个地址不会被当作不稳定多 IP。历史只保留最近 30 分钟、每个代理最多 120 个样本；未观察的时间不算验证通过。
- 多个请求末端不等于已经证明多个公网 IP。完整解析的同终端 HTTP/SOCKS 服务可合并比较；无法解析的提供者、特殊 YAML 或不同末端只提示待确认，不推测公网地址。
- “当前连接一致”（详情中为“当前观测一致”）仅指本轮已采 TCP 路径和代理采样的证据，没有保证未来永不换 IP。混合端口的进程/域名分流、TUN、远程代理、环境变量或中转桥接可能使模型请求与探测地址出口不同；证据不足时保持待确认。不会改变 Clash 选择、添加临时代理端口或中断用户连接。
- 自动检查的进程信息和配置只在本机读取。出口历史是独立的 `route-observations.json`，配置导出和源码/便携包均不包含它，也不存储节点密码或登录凭据。

## 校园网自动保护

默认自动识别当前网络的 SSID、Windows 网络配置与教育域 DNS 后缀，包含 eduroam；无线和有线网络都可参与，不写死任何学校。名称相似但依据不足时列为疑似，点击“记为校园网”或“记为普通网络”确认一次。识别是基于本机特征的判断，不能自动准确识别全世界所有校园网，同名网络或伪造 DNS 后缀也可能影响判断。

默认可自动发现正在运行的 Clash/Mihomo、sing-box、xray/v2ray 内核，后续识别到的新内核路径会加入本轮守护范围。也保留手动网络匹配式、普通网络覆盖和受限 EXE 列表，自动识别可关闭。自动检测不是系统强制网络沙箱，新内核首次启动到下一轮检测之间存在时间窗口。

- “保存并预览”只保存用户配置和显示匹配结果，不改防火墙。
- “启用自动保护”经过说明与 Windows UAC，复制单文件程序到受管理员保护的 Program Files 目录，将策略放入受保护的 ProgramData 目录，创建 SYSTEM 启动任务。
- 后台每约 5 秒检查网络，匹配校园网时启用**指定程序**的出站阻断规则，其他已识别网络关闭这些规则。未知网络默认阻断指定程序，可通过复选框调整。
- 仅管理 `CodexToolbox Campus Guard` 规则组和 `CodexToolbox-CampusGuard` 任务，不修改全局默认策略或其他软件规则。防火墙关闭、任务心跳过期时显示异常，不能据此宣称联网已被限制。
- 保存/导入配置不会更新已安装的机器策略；修改后点击“更新自动保护”。关闭内核自动发现时，客户端更新导致路径变化需要重新选择并更新保护。
- 停用按钮请求管理员授权并移除本工具的任务、策略和规则。受保护的程序副本可能保留，避免清理错误影响其他文件。
- 学校由网络名称识别，并不是认证机制；同名网络可能触发规则。规则会影响所选程序的所有出站流量。不要选择普通浏览器，除非确实想限制它。

本机旧版集成不会自动被替换；若已安装其他校园网保护，独立规则仍然按其自身策略生效。

## 配置和分享

默认配置为 `%LOCALAPPDATA%\CodexToolbox\settings.json`。可通过 `--data-dir "D:\MyToolboxData"` 指定目录；本机可在 `HKCU\Software\CodexToolbox` 的 `DataDirectory` 字符串指定默认位置。发布包本身不含个人配置。

也可以运行 `Codex工具箱.exe --set-default-data-dir "D:\MyToolboxData"`，让程序在独立桌面进程中设置自己的默认目录；之后双击 EXE 即使用该目录。此方式也适用于从 MSIX 应用启动时注册表视图不同的环境，不需要管理员权限。

每次保存保留上一份 `settings.json.bak`。控制接口密钥通过当前 Windows 用户的 DPAPI 加密保存；复制加密内容到其他电脑不能解密。

设置页可导入/导出 JSON。导出会移除接口密钥、Codex 登录目录与旧版脚本集成；**仍包含代理地址、预期 IP、线路名称、校园网络和程序路径**，分享前需自行检查。导入清除密钥、登录目录和旧版集成，不会自动启用或更新机器保护。

## 键盘

- F5 / Ctrl+R：刷新总览。
- Ctrl+N：添加线路。
- Ctrl+1 至 Ctrl+5：切换页面。
- 结果窗口 F5 重试、Ctrl+Shift+C 复制全部、Esc 关闭。
- 实测 IP 可点击复制，文本输入框使用标准选择、复制和 Tab 操作。

## 从源码构建

使用 .NET 8 SDK，在项目目录运行：

```powershell
dotnet publish .\CodexToolbox.csproj -c Release -o .\dist\win-x64
```

不依赖第三方 NuGet 包。源码不含个人账号标识、代理节点凭据、auth.json 或运行日志。运行时缓存恢复可能需要访问 Microsoft NuGet。

基础回归：运行 `CodexToolbox.exe --self-test`，结果保存到当前用户临时目录的 `CodexToolbox-selftest.json`。`qa/Native-Simple.ps1` 提供功能检查，`qa/Native-Responsive.ps1` 提供缩放、侧栏、大小窗口与弹窗检查，运行时必须传入明确的测试进程与证据目录；原有其他 QA 脚本针对旧版布局。不要对正在手动编辑的窗口运行自动化。

## 验证状态

已在 Windows、150% DPI 实机检查多线路增删改、非法 IP 校验、失败反馈、配置备份、Clash 择优版状态和代理公网出口；本机旧版浮层集成亦实际检查。自包含 x64 包可以独立运行。

2.3 参考用户提供的浅蓝灰界面：细描边圆角面板、浅蓝导航选中态、按宽度重新排版的线路与额度卡片。50 项受控回归通过；已在本机实际 150% Windows DPI 下检查默认/600×460 DIP/最大化窗口、75%–150% 应用缩放、侧栏收起、表单展开与弹窗，并检查诊断操作。没有把本机测试宣称为其他显示器、触摸硬件或 ARM64 设备已实测。跨显示器 DPI 切换采用 WPF PerMonitorV2 与工作区边界适配，仍需其他设备验证。

2.2 简化首页、额度、校园网与设置入口，技术细节按需展开。48 项受控回归通过；零手动线路的原生窗口检查通过自动发现两个真实 Codex、各自的登录目录、已有浮层识别、四项诊断结果，以及 150% DPI 默认/最小窗口截图。新的自包含额度读取逻辑已通过本机两个账号和各自代理实查。其他电脑、未开启窗口接口时的独立浮窗以及全新直接添加的视觉呈现尚未跨设备端到端验收；本机现有已批准浮层保持原样。
2.1 的 42 项回归包括单实例/多实例/独立 CLI 分组、非固定 IP、多出口和动态变化区别、双栈、无法读取的进程、校园确认/普通网络覆盖、未知 Wi-Fi 等。另在**零手动线路**的独立数据目录，实际自动发现本机两个桌面实例、匹配其请求/代理并采样；通过原生窗口操作检查历史列表、校园/普通网络记忆和代理内核自动发现。单窗口和独立 CLI 的覆盖来自受控回归，并未关闭本机现有 Codex 窗口来伪造验收。

校园规则匹配与输入验证已回归；完整 SYSTEM 安装/卸载及真实校园网络切换尚未在此发布候选上做端到端验收，需在测试环境启用后验证，不能将预览等同实际阻断。本次本机旧有校园保护没有被替换或关闭。其他电脑上的独立账号额度查询尚未做账号实测。
